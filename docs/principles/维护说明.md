# 原理说明的维护约定

## 目的与入口

[`index.html`](index.html) 用简单语言解释本项目为什么这样计算、每一步做什么，以及怎样确认结果可信，读者不需要预先了解有限元或流固耦合。它随项目功能逐步扩充，不取代 [spec.md](../../spec.md)、[gola.md](../../gola.md)、[agent.md](../../agent.md) 和 [`docs/validation/`](../validation/) 中的验证记录。

浏览器直接打开 `index.html` 即可阅读。采用静态 HTML、内嵌 CSS 和必要的内嵌 SVG，不依赖网络、服务端、第三方脚本或生成工具。源码、测试与验证记录的链接用于定位资料，阅读这些资料可使用编辑器。

## 什么时候更新

新增功能或改变数学模型、输入含义、边界处理、求解方式、输出含义、验证方法时，在同一开发任务中更新对应章节与状态表；已有功能获得新验证证据或状态变化时也更新。仅内部重构、格式调整无需增加原理内容。

每个功能章节依次回答：

1. 它解决什么问题？用一个简单例子说明。
2. 程序怎样做？先解释过程，再介绍术语。
3. 必要公式表示什么？写清符号、单位和适用条件。
4. 如何判断算得对？链接实际测试或验证说明。
5. 当前做到哪一步？分别说明已实现、已验证和计划内容。

更新页面末尾记录（日期、章节、变化、证据）。功能状态必须以仓库事实为依据；存在测试文件不等于测试已通过。教学图、示意流程与真实计算结果必须分别标明。尚未实现的功能（例如整体耦合、FSI2）保持"计划"标记，不得提前写成已验证。

## 独立性与检查

文档只放在 `docs/principles/`，并从 [README](../../README.md) 提供入口。不添加到包构建、求解器运行路径或数值测试判定中，不调用求解器、不修改配置、不读取或覆盖实验数据。无需增加新依赖。

更新后检查 HTML 标签、章节导航锚点、本地资料链接，并在可用浏览器中检查宽屏和窄屏布局。无法进行的检查在交付中说明。仅文档改动不要求重跑数值测试；涉及计算功能的改动仍按 [AGENTS.md](../../AGENTS.md) 和 [spec.md](../../spec.md) 的规则完成本地验证。

开发任务结束前确认：原理解释与实现一致、功能状态有依据、验证来源可找到、更新记录完整。该要求已写入根目录 `AGENTS.md`，供后续开发者和代理遵循。
