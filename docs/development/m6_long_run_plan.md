# M6/T24：长时实验与显式断点续算

日期：2026-10-12。单一执行者承担 A0/A5/A7；自查，不声称独立复核；不提交、不推送。基线为 `1614dc9` 加上一轮未提交的 IQN 公式修正与瞬态接入（621 passed、2 skipped）。

## 目标与必要准备

先开展统一 `cases/fsi2.json` 的 IQN 长时运行（h=0.02、dt=0.01、BDF2、目标20 s），用已冻结的物理门控和周期门槛判断结果。上一轮0.5 s已有50步证据，但 solution.npz 没有完整两层BDF历史，不能用于续算。长时计算前增加显式 checkpoint，避免失败后重复已验证的前缀。

## 文件与接口

- 新增 `validation/fsi2_checkpoint.py`，用单个NPZ保存完整 AcceptedState：全部固体/流体/网格历史、压力、当前网格/网格速度、界面、预测器、接受步/时间/代次和监测账本。JSON元数据嵌入NPZ，不允许pickle；临时文件写完后原子替换。
- `run_fsi2_cli` 与 CLI增加显式 `--resume PATH`、`--max-steps N`。默认仍为完整新运行；成功接受步骤后保存checkpoint。分段截止但未到目标时间时为INCOMPLETE；不把部分区间冒称目标完成。
- 恢复必须核对配置（仅允许目标end_time延长）、网格摘要、求解源码摘要、状态形状/有限值/时间/代次/历史层数与监测顺序。拒绝旧solution.npz、损坏/不匹配checkpoint，验证完成前不加载live root。
- 恢复采用现有 `StateCoordinator.load`，不改变BDF、物理残差、离散、界面传递或事务实现。失败仍保留最后已接受checkpoint；输出失败不得标记成功。
- 新增 `tests/test_fsi2_checkpoint.py`；README、spec/gola/agent、原理页和 `docs/validation/m6_long_run.md` 同步。

## 开始执行前冻结的验收

1. BDF1/BDF2、IQN与整体路径：连续4步和保存2步/新驱动恢复后再2步逐数组一致；BDF2恢复后的阶次仍为2，三个历史代次每步只增加一次。
2. 输入、网格、源码、数据形状、历史层数、时间/代次及监测记录被篡改时拒绝，live root不变。
3. 原子写故障保持已有checkpoint可加载；物理失败保留最后已接受步骤，重试无重复监测行。
4. 分段CLI的checkpoint可显式恢复，短程与未达目标保持INCOMPLETE/退出码3，输入/输出失败为2；旧入口兼容。
5. 相关测试与完整回归通过；真实网格短程连续/分段比较沿用T24逐变量判据（rtol=1e-8、atol=1e-10·S）。
6. 然后运行IQN正式配置至20 s或明确数值失败；每步全残差≤1e-7、连续性≤1e-10、质量≥0.1及正Jacobian均不放宽。周期与参考门槛严格沿用T24。
